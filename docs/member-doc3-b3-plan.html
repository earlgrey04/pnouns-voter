pNouns ⚡ DAO ・ 資料 3/3 — 次の一手(検討中の推奨案)

B3 案: いまの Snapshot 投票をそのまま、Nouns DAO への反映だけ自動化する

2026年8月20日 ・ アールグレイ ・ 資料 2 の仕組み(pNouns Voter)の安全性はそのままに、メンバーの投票体験を一切変えない改良案です。

1. 発想

Snapshot の投票は、実はメンバーがウォレットで署名したメッセージ(どの提案に・どの選択肢か)で、署名データは誰でも取得できます。資料 2 のコントラクトは「専用ページで作った署名」を検証していますが、検証する署名を Snapshot の署名そのものに差し替えれば、メンバーは今までどおり Snapshot で投票するだけで、あとは全自動になります。

2. しくみ

メンバー今までどおり Snapshot で投票画面も手順も変化なし。ガス 0 円。
リレイヤー署名を取得して投函Snapshot から投票署名を取得し、まとめてオンチェーンの pNouns Voter(B3 版)へ。ガスは預け金から払い戻し(誰が投函しても可)。
コントラクト検証・集計「この署名は本当に pNouns 保有者が Snapshot のこの提案に投じたものか」をコントラクトが検証して集計。偽造・改ざん不可。
→ Nouns DAO自動で投票締切後に execute → castVote。資料 2 と同一。

4. 検討した他の案(不採用の理由)

  • 結果報告型(オラクル): リレイヤーが「結果」を報告する方式。最も簡単だが、報告者の鍵が事実上の投票権になるため不採用。
  • oSnap(UMA): Snapshot 公式の実行機能。賛成/反対を選ぶ投票形式と相性が悪く、保証金・異議期間の運用も増えるため見送り。
  • L2 でオンチェーン投票: L2→メインネットの正規ブリッジは 7 日かかり間に合わず、代わりにリレイヤーが橋渡しすると結局「報告型」と同じ信頼モデルに落ちる。メンバーの手間(L2 切替・tx)も増えるため不採用。メインネット投函は 1 票約 1 円なのでガス面の利点もない。

5. どの案でも共通で必要なこと

  • Nouns 投票権の委任先変更: Nouns NFT を持つマルチシグが、新しいコントラクトへ delegate する(1 tx・いつでも戻せる・NFT は動かさない)。
  • シャドー運用から開始: 委任前にメインネットへ「Nouns には投票しないモード」で置き、実際の提案で Snapshot の結果と突き合わせてから本番切替。
  • トレジャリーからガス用 ETH の預け入れ(提案: 0.05 ETH ≒ 1.5 万円。残高はオンチェーンで透明、余りは回収可)。

6. 提案する進め方

  1. B3 版の技術調査(Snapshot の署名仕様・投票し直しの扱い)と実装 → Sepolia で再テスト → 再監査
  2. メインネットにシャドー運用でデプロイ、実提案で Snapshot と一致することを数回確認
  3. メンバー合意 → マルチシグが委任 → 本番運用(以後、Nouns への反映は無人)
メンバーの皆さんに伺いたいこと: ① この方向(B3)で進めてよいか ② 委任先変更とガス預け入れへの合意 ③ すぐの自動化を優先するなら完成済みの A 案(専用ページ)で先に始める選択もあります — どちらを先にするか。
