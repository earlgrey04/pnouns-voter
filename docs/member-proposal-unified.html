pNouns ⚡ DAO — 運営からの提案

Snapshot での投票はそのまま。その前後の手作業をなくします

2026年8月20日 ・ アールグレイ ・ 「いまの仕組み」と「新しい仕組み」を並べて、何が変わり、何が変わらないのか、費用はどうなるのかをまとめました。提案する仕組みは、実際の Snapshot とテストネットの Nouns DAO で動作確認を進めています。

用語
ローカル アールグレイの自宅 PC クラウド ネット上のサービス(Snapshot / Cloudflare / GitHub / Discord) オンチェーン Ethereum 上(改ざん不可・誰でも検証可) 人人の作業　自動プログラム

1. 提案 1 本ごとの流れ

いまの仕組み

  1. 自動ローカル 自宅 PC が Nouns の新提案を検知し、AI で日本語要約を作る
  2. 人クラウド アールグレイが要約を確認・修正して承認
  3. 自動クラウド Snapshot に投票ページを作成(本文＝日本語要約)
  4. 人クラウド Discord に「投票してください」と告知
  5. メンバークラウド Snapshot で投票(署名・ガス代 0 円)
  6. 人オンチェーン 締切を見張り、結果を確認し、自分のウォレットから Nouns DAO に投票
  7. 人クラウド Discord に結果を報告

新しい仕組み

  1. 自動クラウド Nouns の新提案を検知(自宅 PC 不要)
  2. 自動クラウド Snapshot に投票ページを作成。本文は Nouns の提案文をそのまま転記(長すぎる場合のみ末尾を省略し、原文リンクを表示)
  3. 自動オンチェーン 「この Snapshot 投票は Nouns の第 N 号議案のもの」という対応付けを記録
  4. 自動クラウド Discord に告知(投票リンク・締切つき)
  5. メンバークラウド Snapshot で投票 (画面も手順も変わりません・ガス代 0 円)
  6. 自動オンチェーン 投票の署名がコントラクトに届き、本物か検証され、NFT の枚数で集計される
  7. 自動オンチェーン 締切後、コントラクトが集計どおり Nouns DAO に投票
  8. 自動クラウド Discord に結果を報告(検証リンクつき)
変わること
  • 人の作業がなくなります(要約の承認・告知・Nouns への投票・結果報告)。自宅 PC への依存もなくなります。
  • Snapshot の提案文が「日本語要約」から「Nouns の原文(英語)そのまま」に変わります。画像や見出しもそのまま表示されます。日本語の要約は別途 Discord に投稿する形を予定しています(自動化するかは検討中)。
変わらないこと: メンバーの投票体験。今までどおり Snapshot で、署名だけ・ガス代 0 円で投票します(ETH を持っていないウォレットでも投票できます)。

2. 誰が何を持っているか

いまの仕組み

  • Nouns の投票権 … マルチシグ → アールグレイ個人のウォレットに委任
  • 投票の判断 … 人が Snapshot の結果を読んで手で実行
  • Snapshot の結果とオンチェーンの投票の対応は、外部から検証できない
  • アールグレイが不在・多忙だと止まる

新しい仕組み

  • Nouns の投票権 … マルチシグ → コントラクトに委任(個人は持たない)
  • 投票の判断 … コントラクトが署名を検証して自動集計。運営もクラウドも結果を変えられない
  • 集計の内訳が Nouns DAO の記録に残る(下記)。誰でも Snapshot の公開署名から検算できる
  • クラウドが止まっても投票は無効にならない。誰でも代わりに反映・実行できる(下記)

新しい仕組みで使う 3 つの鍵(役割分担)

役できることできないこと置き場所出番
リレイヤーSnapshot の署名をチェーンに運ぶ票の偽造・改変・勝手な投票
(できるのは遅らせることだけ)		Cloudflare毎分
登録係「この Snapshot 投票は Nouns の第 N 号議案のもの」と登録票に関する一切の操作自宅 PC の専用鍵提案ごとに 1 回
管理者緊急停止、ガス代の管理、除外設定票の作成・改変、Nouns への任意の投票pNouns マルチシグほぼ出番なし

いちばん漏れやすい場所(クラウド)に、いちばん弱い権限しか置かない設計です。仮にクラウドが乗っ取られても票の偽造はできず、対処は鍵の差し替えだけで済みます。誤った対応付けに備えて、登録から一定時間は票を受け付けない猶予も設けています。

クラウド(Cloudflare)が止まったらどうなるか

票そのものは Snapshot に残っているので消えません。締切まで 24 時間の余裕を持たせているので、ほとんどの障害は自動で吸収されます。手動の出番は、長時間の停止が締切に重なった場合だけです。

状況どうなるか必要な操作
数分〜数時間の停止
(ほとんどのケース)		復旧後に自動で取りこぼしを取り戻します。どこまで反映したかはチェーン上の記録で判断するため、二重計上も取りこぼしも起きませんなし
リレイヤーの不具合・残高切れ
(投票ページは動いている)		Discord に⚠️警告が出ます。投票ページの「手動で実行」ボタンが使えますウォレットを接続してボタンを押す
Cloudflare ごと停止したまま締切仕組みとしては運営以外の誰でも実行できます技術的な操作が必要: Etherscan の画面からコントラクトの execute を呼ぶ(ウォレット操作に慣れている方向け)。未反映の票がある場合は、公開しているプログラムの実行が必要(開発者向け)
誰も実行しなかったその提案について Nouns DAO への投票が行われません(＝いまの仕組みで投票し忘れたときと同じ結果)—

正直に言うと、最後の手段(Etherscan からの実行)はどなたでも気軽に、とまでは言えません。ウォレット操作に慣れた方であれば運営抜きでも実行できる、という位置づけです。ここで大事なのは「運営だけが持つ特権ではない」こと — 運営が対応できない状況でも、仕組みが誰かの手で前に進められる余地が残してある、という点です(手順書は用意します)。

Nouns DAO に何が記録されるのか

Nouns DAO の投票は「賛成/反対/棄権」だけでなく理由文を添えられます。新しい仕組みでは、そこに pNouns 側の集計を自動で書き込みます。テストネットでの実際の記録:

記録先内容
Nouns DAO(VoteCast)投票者 = pNouns Voter コントラクト ／ 議案番号 ／ 賛否 ／ 票数 ／ 理由文「pNouns holders voted on Snapshot …: FOR (tokens for/against/abstain = 3/0/3, voters = 2/0/1)」
pNouns Voter(Executed)最終集計(賛成/反対/棄権の枚数と投票者数)
pNouns Voter(1 票ごと)誰が・どの選択肢に・何枚で・いつの署名で投票したか

理由文は nouns.wtf の提案ページにコメントとして表示されるため、Nouns コミュニティ全体から「pNouns がどういう内訳でその判断をしたか」が見えます。また Snapshot の署名は誰でも取得できるので、第三者が自分で集計し直して記録と突き合わせる検証も可能です。

4. 動作確認の状況

テスト環境: 投票は本物の Snapshot(テスト用スペース)。Nouns DAO 側は公式テストネット(Sepolia)にある、Nouns 開発チームが公開している本番と同一プログラムのテスト版 DAO。pNouns NFT も本物と同じプログラムの複製を使用。

  • 人手ゼロの通し(複数回): Snapshot の票を自動で集計 → Nouns DAO へ投票 → Discord 報告まで確認。賛否が同数のときの判定、投票がゼロのときに投票しない挙動も確認済み。
  • 実際の画面からの投票: アールグレイが snapshot.box から普段どおり投票し、保有枚数分が集計に反映されて Nouns DAO へ自動投票されることを確認。
  • 過去の本物の投票で検証: Prop 989 に実際に投じられた 3 票の署名を使い、オンチェーン検証と集計が成立することを確認(投票の重みも保有枚数と一致)。
  • 第三者による監査を 9 回実施(AI 監査ツール Codex)。重大な欠陥はゼロ。指摘された 50 件超はすべて修正・再検証済み。

残っている確認: ① 新しい形式(Nouns 原文の転記)での提案作成 ② 本番と同じ鍵の分担(管理者・登録係・リレイヤーを別の鍵にする)での通し ③ メインネットでの「見学モード」。①②はテストネットで数日中に、③はメンバーの皆さんの合意後に行います。

5. 投票のルール(コントラクトに固定)

  • 重み = 保有 pNouns 枚数(チェーン上で検証)。トレジャリー分(13 枚)は数えない。定足数なし。
  • 同数なら投票者数が多い方、それも同数なら棄権 (暫定 — ご意見で変更可能)。誰も投票しなければ Nouns にも投票しない。
  • Snapshot で投票をやり直した場合は、いちばん新しい投票が有効。
  • 締切は Nouns の投票終了の 24 時間前(いまの Snapshot 48 時間より長く投票できます)。
  • コントラクトは後から書き換え不可。NFT や資産は預けません(預けるのはガス代のみ)。

6. 導入の進め方

  1. 見学モードで設置 — Nouns には投票せず、集計だけを実際の提案で数回行い、いまの手動運用と結果が一致するか確認します。
  2. 一致を確認 → メンバーの合意。
  3. マルチシグが投票権の委任先をコントラクトへ変更(1 トランザクション・いつでも戻せる)＋ トレジャリーからガス代を預ける → 本番開始。
本番移行時に必要な準備
  • Discord の通知先の切り替え: 現在テストの通知はアールグレイのサーバーに送っています。本番では pNouns⚡DAO サーバーの Webhook を発行し、告知(📢)・反映(🗳️)・投票完了(✅)・障害警告(⚠️)を pNouns のチャンネルに流します。投稿先チャンネルとロールメンションの有無は、事前に相談させてください。
  • 3 つの鍵の準備: 管理者(pNouns マルチシグ)・登録係・リレイヤーを別々に用意します。
  • ガス代の預け入れ: トレジャリーから 0.05 ETH 程度。
やめたくなったら、マルチシグが委任を戻すだけで元の手動運用に戻せます(Nouns の仕様上、切り戻しは以後の提案から有効。進行中の提案は管理者が停止スイッチで止められます)。
