pNouns ⚡ DAO ・ 資料 1/3 — 現行の運用

いまの「Snapshot 投票 → Nouns DAO 反映」のしくみ

2026年8月20日 ・ アールグレイ ・ Nouns DAO の提案を pNouns の Snapshot に映して投票し、結果を Nouns DAO に届けるまでの現行フロー。どの作業が「人」で、どれが「自動」で、それぞれ「どこで」動いているかを整理しました。

この資料での場所の表し方
ローカル アールグレイの自宅 PC で動くもの(PC が止まると止まる) クラウド インターネット上のサービス(GitHub、Cloudflare、Snapshot、Discord など) オンチェーン Ethereum ブロックチェーン上(誰も改ざんできず、誰でも検証できる)

1. 全体の流れ(提案 1 本あたり)

自動ローカル① 検知・要約自宅 PC の常駐プログラムが 15 分ごとに Nouns DAO を見張り、新しい提案(投票開始)を見つけると AI で日本語要約を作り、GitHub に下書きを提出。
人クラウド② 承認アールグレイが GitHub 上で要約文を確認・修正して承認(マージ)。
自動クラウド③ Snapshot に提案作成承認を合図に GitHub Actions が、bot 用ウォレット(pNouns 1 枚保有)の署名で Snapshot(pnounsdao.eth)に投票ページを作成。期間 48 時間。
人(下書きは自動)クラウド④ 告知告知文は自動生成 → アールグレイが確認し、本人アカウントで Discord の #🔥｜p⚡雑談 に投稿。
メンバー → 人クラウド→オンチェーン⑤ 投票と反映メンバーは Snapshot で投票(署名のみ・ガス代 0 円)。締切後、アールグレイが結果を確認し、Nouns の投票権を委任されたウォレットから手動で Nouns DAO に投票(ここだけオンチェーンの操作)。結果報告も手動。

2. 構成要素と動作場所

要素場所役割
検知・要約プログラム(pnouns-mirror)ローカルNouns 提案の検知、日本語要約、GitHub への下書き提出
GitHub(リポジトリ + Actions)クラウド要約の承認フローと、Snapshot への提案作成の実行(bot ウォレットの鍵を保管)
Snapshot(pnounsdao.eth)クラウドメンバーの投票所。投票は「署名」だけなのでガス代は一切かからない。重み = pNouns 保有枚数、定足数 210、期間 48h
告知プログラム + Discordローカル+クラウドSnapshot 投稿を検知して告知文を下書き → 人の承認後に投稿
Nouns NFT(2 枚)を持つマルチシグと、その委任先ウォレットオンチェーンNouns DAO への投票権。投票の操作(トランザクション送信)は毎回、人が手動。このガス代(数十円〜)は Nouns DAO から自動で払い戻される

3. 現行の課題

  • 最後の反映(⑤)が手動: 締切の見張り → 結果確認 → Nouns DAO への投票 → 結果報告、が毎回人の作業。遅れ・忘れのリスク。
  • 属人化: ②④⑤がアールグレイひとりに依存。不在時は止まる。
  • ローカル PC 依存: ①の検知は自宅 PC が動いている前提。
  • 「Snapshot の結果」と「Nouns DAO 上の投票」のつながりが、外部からは確認しにくい。

この⑤の手動をなくす仕組みを作り、テスト環境で動かしたのが資料 2 です。
